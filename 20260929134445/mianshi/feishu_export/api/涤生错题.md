Hadoop 实现的两大功能模块是 

HDFS 和 MapReduce。

在生产环境下，一般使用

完全分布式模式来安装 Hadoop 集群。

MapReduce程序中默认采用的切片机制是

FileInputFormat切片机制。

在Hadoop中，FileInputFormat是MapReduce框架的输入格式类，用于将输入数据切分成逻辑上的块，称为切片（slices）或分片（splits）。每个切片由一个Map任务处理。FileInputFormat将输入文件切分成固定大小的块，通常每个块大小为HDFS块大小（默认为128MB）。切片机制的目的是使得多个Map任务可以并行处理输入数据的不同部分，从而提高整体的处理效率。

在Hadoop写流程中，数据块的拆分是在数据输入阶段由数据MapTask阶段的 server 端进行操作的。

在Hadoop中，数据块的拆分是由输入格式（InputFormat）的实现控制的。在数据输入阶段，输入格式负责将输入数据切分为逻辑上的块或切片（slices）。每个切片对应一个Map任务的输入。默认情况下，Hadoop使用FileInputFormat作为输入格式，在服务器端进行数据块的拆分操作。

在MR程序中，修改默认切片算法的是job.setInputFormatClass(CombineTextInputFormat.class)。

如果要修改默认的切片算法，可以使用job.setInputFormatClass()方法来设置自定义的输入格式类。其中，CombineTextInputFormat是Hadoop提供的一个输入格式类，它可以修改切片算法以支持合并小文件，从而减少Map任务的数量。

选项 A、job.setOutputKeyClass(Text.class)是用于设置输出键的类型。

选项 C、job.setMapperClass(TokenizerMapper.class)是用于设置Mapper类。

选项 D、job.setCombinerClass(IntSumReducer.class)是用于设置Combiner类。

Map任务的数量是由输入文件的个数大小以及切分算法的组合决定的。

与HDFS建立连接，建议使用的是 A、conf.set("fs.defaultFS", "hdfs://dscluster") 这种链接方式。

conf.set("fs.defaultFS", "hdfs://dscluster") 设置了文件系统的默认URI为"hdfs://dscluster"。这里的 "dscluster" 是HDFS集群的命名空间，而不是具体的主机名或端口号。这种方式适用于使用了HDFS高可用（HA）配置的情况，其中 "dscluster" 是HA集群的命名空间。

将程序提交到Hadoop集群运行的命令是 A、hadoop jar wordcount.jar classname。

在Hadoop中，可以使用`hadoop jar`命令将打包好的Java程序（JAR文件）提交到集群上运行。这个命令后面需要指定JAR文件的路径和程序的类名

选项 B、hdfs jar wordcount.jar classname 是错误的，`hdfs jar`命令是用于在HDFS上执行JAR文件，而不是将程序提交到Hadoop集群运行。

NameNode是Hadoop分布式文件系统（HDFS）的关键组件，负责管理文件系统的命名空间和元数据。它维护文件和目录的层次结构，存储文件的元数据信息，以及监控和管理数据块的分布。

定期进行block report：是NameNode的功能之一。Datanode会定期向NameNode发送block report，汇报它所持有的数据块信息。
