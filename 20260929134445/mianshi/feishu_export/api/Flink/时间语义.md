时间语义是个是什么东西

我们知道Flink的无线数据流是一个持续的过程，时间是判断业务状态是否滞后的重要依据

哪这里的时间分为：**Event time（事件时间）、Ingestion time（摄入时间）、Processing time（处理时间）**

但是从1.2版本之后默认是根据EvenTime ,之前默认的是**Processing time**

## **Event time**

是每个独立事件在产生它的设备上发生的时间，

**比如现在2026年9月30日23点59分59秒下单了一个东西，此时此刻就会给你这个事件打一个水印，就是某某某，在某台机器上下单的时间是多少，那这个时间就是所谓的一个事件时间**

比如一条具体的前端埋点数据日志，当用戶在触发的时候就会产生一条日志，那么事件时间就是这条日志产生的时间。

**这个时间通常在事件进入Flink之前就已经嵌入到事件中了，并且事件的时间戳是可以从记录中抽取出来的。**

**在事件时间中，时间进度依赖于数据而不是其他形式的时钟**

事件时间程序必须要指定如何产生**事件时间水印(Event Time Watermarks)，**这是事件时间处理进度的信号机制

**在 Flink 的流式处理中，绝大部分的业务都会使用 Event Time，一般只在Event Time 无法使用时，才会被迫使用 Processing Time 或者 Ingestion Time**

##  Ingestion Time（摄入时间）

数据进入Flink的时间，如某个Flink节点的source operator接收到数据的时间，在source操作中每个记录都会获得source的当前时间作为时间戳，如果使用了Ingestion Time，那么后续基于时间的操作会依赖这个时间戳

## Processing Time（处理时间）

是指执行程序（每个算子）时对应的task所在物理机的系统时间，是Flink 1.12之前默认使用的时间。当一个流程序通过Processing Time来运行时，所有基于时间的操作将使用各自操作所在的物理机的系统时间。例如：一个每小时处理的时间窗口将包括所有在系统指定的一个小时内到达指定操作的所有记录。

## WaterMark（水印)

### 乱序问题：

Event Time是最能反映数据的时间属性，但是Event Time可能会发生延迟或乱序

flink本身只能逐个处理数据， 

**假设一个流式系统目前正在接收并处理用戶手机的日志，但是由于网络延迟，或者用戶手机离线，比如飞机，隧道这种。导致日志没有及时发送到流式系统，流式系统观察到数据的时间和数据真正产生的时间可能存在偏差**

比如我真正产生的时间是9点10分，我通过一个山洞过个1分钟才把数据发送到，流式系统接收到这个消息已经9点11分了

#### 如何应对Event Time可能会发生延迟或乱序情况呢？

比如需要统计从10:00到11:00发生某个事件的次数，也就是对Event Time是在10:00和11:00之间的数据统计个数

Event Time可能会发生延迟或乱序的情况下，Flink系统怎么判断10:00到11:00发生的事件数据都已到达，可以给出统计结果了呢？

### WaterMark引用

流处理从事件产生，到流经 source，再到 operator，中间是有一个过程和时间的，虽然大部分情况下，流到 operator 的数据都是按照事件产生的时间顺序来的，但是也不排除由于网络、分布式等原因，导致乱序的产生，所谓**乱序**，就是指 Flink 接收到的事件的先后顺序不是严格按照事件的 Event Time 顺序排列的。

> 

因此，如果不能明确数据是否全部到位，但又不能无限期的等下去，此时必须要有个机制来保证一个特定的时间后，必须触发 window 去进行计算了，这个特别的机制，就是 **Watermark**。

**Flink是用 Watermarks 来实现 Event Time 的核心功能，用于处理乱序事件，正确的处理乱序事件，通常用Watermark 机制结合 window 来实现，数据乱序的问题**

所以水印的作用就是为了调整数据乱序的问题

从上面来看watermark可以理解成一个延迟触发机制，本质上就是一个比较早的时间戳，**代表数据乱序的时间错乱程度。**

**比如可以设置 Watermark 的延时时长 t，每次系统会校验已经到达的数据中最大的 maxEventTime，然后认定 eventTime小于 maxEventTime - t 的所有数据都已经到达，如果有窗口的停止时间等于maxEventTime – t，那么这个窗口被触发执行**。

所以当算子接收到watermark T后，就代表时间T之前的数据已经接收完毕，不会再有小于时间T的数据。即Watermark即为系统可以允许的时间的延迟时间
