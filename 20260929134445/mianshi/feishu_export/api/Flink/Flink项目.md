### lambda架构

这个架构是我们业务上最开始组件对实时提出了一些诉求，去计算一些实时指标

最开始我们肯定是有了离线并且离线也比较成熟了，一般情况下就是说在这个离线数仓的基础上我们会增加一个实时链路，对这个数据进行一个改造 

比如上游数据源：（业务数据库或者日志）这种数据采集到消息队列

在最开始没有flincdc这种的话那其实我们会有flum这种组件或者说a里开源的这个Canal 

他的原理其实就是比如说我们采集这种mesql里面的blog模拟Slave,把这个blog这个消息，二进制数据啊进行解析然后发送到kafka里面。

flum也是一样的，采集一些日志的发布到kafka

**注：Flink CDC 是 Apache Flink 的数据库变更实时捕获连接器套件（Change Data Capture），它让 Flink 能直接把自己变成一个"数据库监听器"，实时读取 MySQL、PostgreSQL 等数据库的 Binlog/Redo Log，把 ****`INSERT/UPDATE/DELETE`**** 操作变成流数据直接处理。**

**CDC（Change Data Capture） = 捕获数据变更的技术。当数据库里的数据发生增删改时，CDC 能实时感知并把这些变更事件推出来。**

接着就是有了消息队列比如发送到kafka这里的话可能有一部分的数据的话就是说flum同步到ODPS 或者hdfs，通过映射的方式同步到hive表里面，那我们就有了离线的这个数据仓库用可以用这个数据源进行数据的建模，

这就是典型的数仓的一个建模：从ods到dwd到dm数据集市，离线有这一套在跑

那么实时这里是下面那一条，实时计算就是说我们定义了消息队列，我们回去做这个明细层，这里ods层就是消息队列，实时明细层，实时订阅之后我们发送到消息队列下游的kafka

因为我们实时明细层还需要对这种实时明细层去做进一步的处理还需要实时的去算，发到kafka，发到kafka再去下游的订阅做汇总的指标，去给到上游做进一步的应用，比如实时看板，大屏

然后比如说我实时做了之后，不需要比如处理完实时明细层之后，我直接写到olap引擎里，比如ch，drois

其实就可以做这种实时的查询了，相当于我实时摄取的这些实时数据就可以实时查询了！但是下一步的处理没法做了因为，到olap组件里，不能通过olap组件发送到kafka，
