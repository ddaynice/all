#### 第一条：埋点采集线

用户在 APP/PC/电视端产生广告曝光或点击行为，埋点 SDK 上报后进入采集平台（atta），按小时分区写入 ODS 层原始日志表。

ODS 到 DWD 做 ETL 清洗：过滤无效事件、空值率校验、业务规则校验（比如曝光量必须大于点击量，异常流量打标），最终产出曝光事实表、点击事实表。DWD 层按天级分区存储。

到 DWS 按 天 + 端 + 广告位 + 广告场景 汇总曝光量、点击量，产出日粒度汇总表。

#### 第二条：业务库同步线

广告主在投放平台创建订单、设置定向策略、调整预算，这些数据存在业务库 MySQL 中。

我们通过 CDC 实时同步 或 T+1 批量同步到 ODS 层，DWD 层做标准化清洗，产出广告主维表、订单维表、广告位维表。

## 什么是雪花模型和星型模型

### 星型模型

星型模型是维度建模最简单的形式，也是数仓以及数据集市开发中用的最广的

星型模型由事实表和维表组成，一个星型模型可以拥有一个或者多个事实表，每个事实表引用任意数量的维表

适用于快速单一业务过程的分析，比如销售报表这种，查询效率高，复杂度简单方便维护，但是冗余高存储占用的大

而且如果新增业务属性的话可能还需要修改维表结构，适应性差点

### 雪花模型

雪花模型是星型模型的扩展，在雪花模型中每个维度都是经过规范化链接到更多维表

和星型模型一样也是一张事实表和多张维表构成

雪花化就是将星型模型中的维度表进行规范化处理

当所有的维度表完成规范化之后，就形成了以事实表为中心的雪花结构

这个查询效率比较低因为要join的表变多了

但是相对的冗余是减少了

复杂度高，适合规范化管理的场景

适用需要节省存储空间的 比如数据量庞大的场景

支持多层级维度分析 如按年 - 月 -日逐层下钻

这里的话优化就往调优上说

优化这里的话两个方面 一个是参数调优，还有就是sql调优

sql这里

比如列裁剪和分区裁剪，主要是用什么取什么，不要用*一股脑的全取出来

提前收敛数据有些条件能先过滤就尽量放到子查询里去，减少输出

谓词下推将过滤将过滤表达式尽可能移动至靠近数据源的位置，这样在map执行过滤条件，减少map端数据输出

还有就是排序，常用的就是order by

只走一个reducer，当表数据量较大时容易计算不出来，性能不佳慎用，在严格模式下需要加limit

**sort by局部排序，单个reducer内有序，把map端随机分发给reduce端执行，如果是要实现全局排序且走多个reducer的优化需求时，可以在外层嵌套一层，例如：select * from (select * from 表名 sort by 字段名 limit N) order by 字段名 limit N，这样就有2个Job，一个是内层的局部排序，一个是外层的归并全局排序**

还有的话就是数据倾斜

倾斜这里的话

如果是group by导致的倾斜

可以把map端聚合开启，减少reduce 的处理set hive.map.aggr=true

开启group-skew的负载均衡，本质上是启动两个MR串行，先随机分区聚合，后按key分区聚合（set hive.groupby.skewindata=true）

还可以给分组字段添加随机数，将key打散统计，再去除随机数进行聚合。（加盐去盐）

在对业务非常熟悉的前提下，将大基数key的record拆分成一张单独的表，对于该key单独进行聚合查询并UNION。

这样左都行

如果是count(distinct xxx) 导致的倾斜，可以改成group by 最后在 count查一次

对于存量小文件

MR中 reduce 有多少个就输出多少个文件

**reduce的个数和分区数最终决定了输出的文件的个数，所以可以调整reduce的个数以及分区 达到控制hive表的文件数量。**

我比较常用的是调参

每个Map最大输入大小(这个值决定了合并后文件的数量)

**set mapred.max.split.size=102400000;**

**个节点上split的至少的大小(这个值决定了多个DataNode上的文件是否需要合并)**

**set mapred.min.split.size.per.node=102400000;**

**一个交换机下split的至少的大小(这个值决定了多个交换机上的文件是否需要合并)**

**set mapred.min.split.size.per.rack=102400000;**

**前3行设置是确定合并文件块的大小，>128M的文件按128M切块，>100M和<128M的文件按100M切块，剩下的<100M的小文件直接合并**

**set hive.input.format=**[**org.apache.hadoop.hive.ql.io**](http://org.apache.hadoop.hive.ql.io/)**.CombineHiveInputFormat;    -- map执行前合并小文件**

**设置map输出和reduce输出合并小文件**

**-- 设置map端输出进行合并，默认为true**

**set hive.merge.mapfiles = true;**

**-- 设置reduce端输出进行合并，默认为false**

**set hive.merge.mapredfiles = true;**

**-- 设置合并文件的大小**

**set hive.merge.size.per.task = 256*1000*1000;**

**-- 当输出文件的平均大小小于该值时，启动一个独立的MapReduce任务进行文件merge**

**set hive.merge.smallfiles.avgsize=16000000;**
