**流量数据域（AMS回传）：**

        此部分数据来源于 cdg ，主要包含硬广和非标的收入、曝光、点击、库存指标，主要用于各个业务方的日常收入盘点和 汇报。

口径是经过了cdg/ pcg/ 销售等多方业务确认过了得。  如果想盘点核心资源/大盘，等非用户粒度的收入，曝光，库存，点击等指标，请使用流量侧数据域，数仓侧已经将上游的多个收入主题整合成了统一的数据源，下游使用的时候，直接从相关的 主题表中拉取的就是各个应用（视频，体育，片多多）的全部收入

 

**用户数据域（AMS回传）：**

此部分数据来源于cdg，主要包括用户粒度的请求、曝光、点击等数据。 由于历史原因，这部分数据和流量侧的数据无法对齐，且各个历史的实验均通过此份数据开展。因此想要分析人粒度的行为指标开展试验，请使用该数据域，指标中包含收入以及点击，曝光等

##### 1.1.2接入的方式

客户端上报这里是通过atta平台接入，这里是数据同步过来的从tdbank同步到tdw库

ams这些回传过来的数据接入方式是接口回传+数据同步

AMS系统 → 接口回传 → 数据同步 → TDW数仓

AMS通过API接口将数据回传给腾讯视频->通过`cdg_omad_interface`库进行数据同步->在TDW中进行ETL处理

Stone：数据同步 +接口对接

招商工作台：数据同步+接口对接

Stone → 数据同步 → 商业化数仓 → 业务应用

招商工作台 → 项目信息同步 → DIM层 → ETL处理 → DWS层 → 口径对齐 → ADS层

接口对接的意思：

比如AMS系统 → API接口 → cdg_omad_interface库 → 商业化数仓

再详细点就是AMS系统 → 接口对接 →临时存储 → 数据同步 → 商业化数仓 → 业务应用

这里的话就是ams系统通过api将数据推送到接口层，接口服务数据接收数据验证权限，数据格式等，然后通过就将数据先存到`cdg_omad_interface`相关表里

第二个阶段就是`cdg_omad_interface`库->数据同步 再到tdw这里
