**体系架构**

Hive是由两个大块构成的，上半部分是hive的组成，下半部分是Hdfs

hive组成分为两个部分 一个是服务端主机 还有一个是客户端主机

客户端组件Web Gui+Cli

服务端组件 Driver MetaStore Thrift这三个组成

其中客户端的Cli是命令行接口，用于连接HiveServer Web Gui这个就是给用户提供的通过网页访问hive的方式

服务端的Driver中包括**Compiler、Optimizer和Executor**

Thrift这是一个跨平台的组件

运行原理

这里也是两哥部分 第一个部分就是HIVE方面的

首先用户通过UI提交sql语句，开始调用Driver的接口，将查询就提交到Driver这里了

第二步Driver拿到查询的请求之后，会为这次的查询创建一个唯一的ID，并且将这个查询发送到Compiler中

第三步就是COMPILER就会生成一个编译计划，有了这个编译计划编译器COMPILER就会向MERA&STORE进行元数据的获取！大白话的意思就是，我有个请求，我需要查一些表，字段，可能还要过滤的东西，就把这些告诉它

第四步MERA&STORE拿到这些信息之后就把COMPILER想要的信息返回给他

第五步编译器拿到元数据之后就会生成一个执行计划，可能是MR的任务也可能是HDFS的操作

同时这个任务就会被发送的DRIVER中

第六步DRIVER拿到这个计划之后就会把这个计划提交给EXECUTIONENGINE引擎，这个引擎就会操控元数据库，得到这个计划需要的一些基础信息

在拿到这些信息之后就会发起一个请求给到JOB TRACKER，进行一个读写的操作，

并且子啊获取到信息后，通过序列化的一个容器。把它写入到一个临时的文件中，这个临时的文件主要是向mr阶段提供数据

在往下就是数据的一个往返的操作了，用户请求获取结果，执行引擎获取到临时存储计算的一个结果，然后逆向的返回到ui

### 3.为什么MapReduce的执行效率很低？

MapReduce的执行效率很低，这种低效是由它的执行模式决定的，所有的Map Task、Reduce Task全部是以进程的方式执行的，要启动进程、销毁进程，即使可以开启JVM重用，但是也是用的时候开启，结束之后关闭，而且JVM成本很高。

随着时代的发展，人们开发出计算处理能力更强大的数据处理工具，如Spark、Tez等，因此有：Hive on MapReduce、Hive on Spark、Hive on Tez

所以Hive底层所支持的执行引擎有MapReduce、spark、tez。

### 4.能讲清楚内嵌模式、本地模式、远程模式的差异。(基本要求)

（1）Embedded metastore：内嵌模式。

其特点是：hive服务和metastore服务运行在同一个进程中，derby服务也运行在该进程中。该模式无需特殊配置。

（2）Local metastore：本地模式。

其特点是：hive服务和metastore服务运行在同一个进程中，mysql是单独的进程，可以在同一台机器上，也可以在远程机器上。该模式只需将hive-site.xml中的ConnectionURL指向mysql，并配置好驱动名、数据库连接账号即可。

（3）Remote metastore：远程模式。

其特点是：hive服务和metastore在不同的进程内，可能是不同的机器。 该模式需要将hive.metastore.local设置为false，并将hive.metastore.uris设置为metastore服务器URI，如有多个metastore服务器，URI之间用逗号分隔。metastore服务器URI的格式为thrift://host:port。

### 10.能讲清楚Hive读写文件的机制。

首先hive是基于hadoop的，所以hive的读写是通过hadoop分布式文件系统hdfs进行的

关于写和读就是序列化和反序列化

读是反序列化

写是序列化

首先从hive的行数据开始通过一系列的序列化把这个数据对象转换成机器能够识别的就比如key value的形式在转换成hadoop的一个存储格式，最终就会把数据以字节码的形式存到hdfs上 这就是序列化的一个操作

反序列化就是将机器码从hdfs中转换成hadoop的一个存储文件 在接着转换成一个键值对 在转换成hive里面的一个字段这就是反序列化的操作

写方面，会将数据拆分成块，然后将这些块放在hdfs上不同的节点上NN,这些就是数据块，通常的话是128M的大小数据块，然后hive使用hadoop的mapreduce框架来进行处理，将这些数据分不到不同的节点上实现并行处理

读方面

hive利用hadopp的输入格式（InputFormat）来读取文件,输入格式定义了将文件划分成输入分片（input split）以便并行的处理数据，每个输入的分片由一个或者多个数据块组成，hive将每个输入分片送给不同的mapper任务进行处理来实现读！

### 12.请讲一下对分区、分桶的理解。

分区和分桶都是细化数据管理

1）从表现形式上：

分区表是一个目录，分桶表是文件

（2）从创建语句上：

分区表使用partitioned by 子句指定，以指定字段为伪列，需要指定字段类型

分桶表由clustered by 子句指定，指定字段为真实字段，需要指定桶的个数

（3）从数量上：

我的理解就是分区是一个目录，是一个用来归类，方便查询的目录，但是分区只是逻辑上的划分他不会实际的存储数据，比如比如我现在有个销售数据的表，日期被定义为了分区，新建分区date=2017

### 16.请讲一下order by、sort by、distribute by、Cluster by的区别。

order by

全局排序；对输入的数据做排序，故此只有一个reducer

sort by

非全局排序，在数据进入reducer前完成排序，当mapred.reduce.tasks>1时，只能保证每个reducer的输出有序，

distribute by

按照指定的字段对数据进行划分输出到不同的reduce中；后面不能跟desc、asc排序；

常和sort by一起使用，并且distribute by必须在sort by前面；

cluster by

相当于distribute by+sort by，只能默认升序，，不能指定排序规则为 ASC 或者 DESC。

### 17.请讲一下left join、right join、inner join、left semi join关联结果的差异，描述它们各自的特性，并举例说明。

左连接：=左交集右+左表

右：右交集左+右表

inner join：只取交集

left semi join

左连接：显示左表的所有记录，如果右表中有匹配的记录，则显示匹配的右表记录；如果没有匹配的记录，则右边的关联字段显示为NULL。

右链接:显示右表的所有记录，如果左表中有匹配的记录，则显示匹配的左表记录；如果没有匹配的记录，则左边的关联字段显示为NULL

inner join:只显示符合条件的记录，不显示左表或右表中未匹配的记录

left semi join:左半连接返回左表中的记录，但只限在右表中存在匹配的记录。如果左表的记录在右表中没有匹配，则不返回。它只传递左表的join key给map阶段，因此在SELECT子句中只能出现左表的字段。

### 18.举例说一下join的MR实现过程。

有两类一类是Commom join（reduce完成的） 还有一类是 MAPJOIN (map阶段)

Commom join 的过程

简单来说join可以分为3个部分

Map阶段

在map阶段第一步是读取原表的数据，那么在map输出的时候是以join on条件中的列为key，这里的key指的就是连接条件，那么如果有多个关联键，则这些关联键的组合为key

在第二步： Map输出的value为join之后所关心的(select或者where中需要用到的)列；同时在value中还会包含表的Tag信息，用于标明此value对应哪个表；

第三步就是按照key进行排序了！

shuffle阶段

根据key的值进行hash，并将key/value按照hash值推送至不同的reduce中，这样确保两个表中相同的key位于同一个reduce中。

reduce阶段

根据key的值完成join操作，期间通过Tag来识别不同表中的数据

Map join：MapJoin通常用于一个很小的表和一个大表进行join的场景，具体小表有多小，由参数hive.mapjoin.smalltable.filesize来决定，该参数表示小表的总大小，默认值为25000000字节，即25M。

首先是task A  这个是一个本地task 它是会扫描小表 扫描完小表之后的话就会把这些数据转换成为一个hash table的结构  并且写入到本地的文件中去 ，接着就加载到了local cash中

然后就是taskb了这个的话就是大表了 并且是一个没有reduce的MR 启动这个task b扫描大表 在这个map阶段大表的每一条数据都会和distrub Cache 中的hash cash进行关联 然后输出结果

但是因为没有reduce所以有多少个map task就有多少个任务！
