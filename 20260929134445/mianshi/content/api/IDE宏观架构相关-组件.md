## ETL和ELT的本质区别？

 大数据本质作用就是存储和计算数据

对于企业来说，数据是庞大的，数据的来源是各种各样的，可能有事实的，离线的，结构的或者非结构的

那么大数据平台首先要做的就是把数据给抽取过来，然后在做一个存储和分析

### Hbase是什么？

首先来说还是数据库（这是网上查的），本质还是键值对，就是一个map,是一个稀疏的，分布式的，持久化存储的多维排序的map，是一个基于Hadoop的分布式，可扩展的，可以大量存储的数据库

#### 分布式：

Hbase是存在分布式文件上的，比如HDFS/s3等等，所以Hbase底层数据是分布存储在不同的服务器上的，这里的HDFS可以看做是硬盘，Hbase基于HDFS存储，不直接操作linux，还是相当于套了一层壳

#### 持久化：

就是数据可以永久的保存在硬盘上

#### 排序的：

这个就是Hbase能够实现高效查询的原因，底层是hdfs，但是Hbase本质就是一个map，kv键值对，但是k是按照字母排序的，有序存放

把k按照字典去排，那么这个时候去找就很快，就像我们查字典，也是先找字母再去找页数，在我们的Hbase就是二分半查找就找出来

### 它主要是干什么的？

它的出现主要是应对大量数据的随机读写需求，可以实现海量的数据实时随机读写!

注意：Hbase是一款 Nosql的Hadoop的组件（核心）

## Kafka

消息中间件 2011年诞生

### kafka是什么？

kafka是一个分布式的支持分区，多副本基于zookeeper协调的分布式消息系统！其实就是一个基于发布和订阅的消息队列

### 应用场景

Jay krep觉得消费者之间的数据太复杂，如果有n个数据源 m个消费者，那么怎么传递nxm个消息

数据源也非常多，消费者也非常多，同一个数据源有很多人去用，那么这个排列组合就非常多

那么如何实现一个管理，然后就是重新迭代开发出来了kafa

### 架构

生产者-缓存-消费者

一个典型的 Kafka 集群中包含若干Producer

若干broker中间的缓存一般broker数量越多，集群吞吐率越高

若干Consumer Group（消费者）

以及一个Zookeeper集群。
