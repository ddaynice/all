## Hadoop

### 优点

扩容能力（Scalable）

能可靠地（reliably）存储和处理千兆字节（PB）数据

成本低（Economical）

可以通过普通机器组成的服务器集群来分发以及处理数据。这些服务器几圈总计 可以达到千个节点。

高效率（Efficient）

通过分发数据，hadoop 可以在数据所在的节点上并行的(parallel)处理它们，这 使得处理非常快。

可靠性（Reliable）

hadoop 能自动地维护数据的多份副本，并且在任务失败后能自动重新部署(redeploy)计 算。

### 缺点

Hadoop 不适用于低延迟数据访问。

Hadoop 不能高效存储大量小文件。

Hadoop 不支持多用户写入并任意修改文件

总体来说Hadoop是大数据最基础的部件，是大数据应用技术的基础

### **NameNode**

文件系统的命名空间、文件系统元数据和数据块的位置信息。

记录了HDFS中所有文件和目录的层次结构，并维护了文件系统中数据块的位置信息。

负责处理客户端的读取和写入请求，像所有跟hdfs访问相关的所有操作，都必须要先和NameNode建立沟通，由他来进行统一的调配

#### 功能

#### **DataNode**

Hadoop DataNode是一个Hadoop集群中的节点类型，主要负责存储和管理Hadoop分布式文件系统（HDFS）中的数据块。

#### **功能：**

一个是数据本身；

一个是元数据（数据块的长度，块数据的校验和，以及时间戳）

#### **工作机制：**

#### **JournalNode**

它主要用于支持HDFS的高可用性和数据恢复功能，用于协调NameNode之间的数据同步。

它可以将NameNode的操作记录（也称为编辑日志）写入到多个JournalNode上，并在NameNode出现故障时，将这些操作记录用于数据恢复。

### Yarn有什么

YARN 是一个资源管理平台，负责管理集群 中的计算资源并使用它们来调度用户的应用。它在整个 Hadoop 系统上执行调度和资源分 配。

简单来说就是一个资源分配管家

#### 四个组件

ResourceManager（资源管理器），NodeManager（节点管理器），

ApplicationMaster（任务管理器），container（容器）

##### ResourceManager（rm）：负责集群所有资源的监控、分配和管理。

##### NodeManager（nm）：负责单个节点的维护，一个集群有多个。

##### ApplicationMaster（am）：负责单个应用程序的调度和协调。

##### Container：虚拟的资源容器，封装了任务所需的资源，如内存，CPU 等。

### **MapReduce是什么**

是一个用于大规模数据处理的编程模型 -用来计算的 一般是放到hdfs上

### 总

## HDFS

hdfs分布式存储就是一个虚拟的存储，我们相当于把多台机器拼成一台机器，所有磁盘集抽象成一个文件系统

hdfs全称是**Hadoop Distributed File System **

官方来说：

当存储的数据量的大小超过一台独立物理计算机的存储能力时，就需要将它进行分区

(partition)并存储到若干台单独的计算机上。**这种存储方式是通过计算机网络与各个单独的 **

**物理节点相连，能够实现文件在网络上的多台主机间共享，允许多机器上的多用户进行文件 **

**分享和存储 - 这就是HDFS 分布式文件系统**

他是hadoop的主要组件，他是一个分布式文件系统

特点就是高容错 价格便宜 高吞吐

### 数据块

HDFS块（block）的概念，它是抽象的块，而非整个文件作为存储单元，在Hadoop2.x版本下，默认大小是128M/256M，且备份3份，每个块尽可能地存储于不同的DataNode中。按块存储的好处主要是屏蔽了文件的大小，提供数据的容错性和可用性。

这个快什么呢，就是把一个文件拆开了，比如哟个文件是1g我给他拆开成每块128m的块，然后放到不同的服务器中，当我要用的时候我再将这些块拿回来。

但是吧这里的数据块 bilock size 只是逻辑上的大小 当实际存储的大小小于这个大小 就是占用自生的大小

##### 说明

这里的block size 只是逻辑上的限定大小.他的意思就是为了方便namenode管理数据存储的一个逻辑概念

真正的物理块是存在datanode服务器上的磁盘上的

而且当一个物理块文件大小小于block size 他是不会占用一个blocksize逻辑大小 ,而是他自 己本身实际的文件大小

##### 但是HDFS里的块为什么这么大?

HDFS 的块比磁盘大,其实最初的目的是为了最小化寻址开销

怎么理解呢?

就是如果块的大小足够大,那么从磁盘传输数据的时间回明显的大于定位这个块开始位置需要的时间

所以传输一个由多个块组成的大文件的时间取决于磁盘的传输速率

##### 数据块的优缺点

1.分散存储

2.简化存储管理

3.增强数据容错性
